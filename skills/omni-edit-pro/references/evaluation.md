# Evaluate routing and actual edit quality

Use this protocol when testing the instruction package or making improvement claims. A correct Markdown link, plausible plan, passing render command or successful routing response does not prove a better video. Keep three evidence levels separate: package checks, instruction/agent behavior tests and executed media comparisons. Record each test as passed, failed or not run with the artifact/version and observed evidence. This document is a protocol; its examples are not completed benchmarks.

When an authoring task supplies no media, instruction traces can establish routing and planned behavior only. They can expose a missing default, an unauthorized layout change or acceptance of a static-card shortcut; they cannot establish the result of rendering that plan. Do not invent source observations, render paths, ratings, participant counts or completed audiovisual review. Use [Quality assurance](quality-assurance.md) and [Delivery](delivery.md) for real output acceptance. The cases below are test definitions, not claims that any test has run.

## Freeze the comparison before tuning

Choose and freeze the relevant untouched baseline snapshot before testing; for a 3.1 change, an unchanged 3.0.0 snapshot is a valid baseline. Record both revision IDs/snapshot paths and keep their instructions and writable run areas separate; do not rewrite the baseline into the new behavior. Use the same supplied media, prompt, host/model configuration, tool versions, available resources and execution limits. Record any unavoidable difference and limit the conclusion accordingly. Keep processing free/local and leave originals unchanged.

The historical 2.0.0-to-3.0.0 Auto comparison checks whether the old snapshot stops at its mandatory questions. Preserve that protocol when reproducing that historical comparison: also run a fairly configured old edit with equivalent explicit output choices so the visual comparison does not punish it simply for missing information its workflow requires. For a newer baseline, test its actual saved behavior rather than assuming it had those questions, a compulsory blue palette or a static-card requirement. Report routing, planned compliance and rendered quality separately. An existing baseline behavior that already meets a new case is a regression control, not an invented failure.

Before running candidates, freeze the development/held-out split, prompts, requested outputs, protected content, scoring dimensions, anchored rubric, reviewer procedure and acceptance gates. Use development footage to revise the instructions. Reserve several independent held-out sources per mode for the final comparison; do not tune on their results and still call them held-out. After tuning from a failed held-out result, use new held-out cases or disclose that the rerun is no longer held-out. Preserve preset regression cases as well as Auto/Reference cases.

Record for each run: case ID; prompt; source/reference/asset IDs and fingerprints; input-role mapping; mode; output set; permissions; versions; source-to-output mapping; decisions; questions/blockers; preview/final paths; review coverage; defects; elapsed processing time; human repair time; and final disposition. One editor owns each source timeline; reviewers may inspect evidence without creating competing timelines. Store candidates and diagnostics in the working area. Only checked completed outputs are promoted as finals.

### Release gates

Hard checks apply to every candidate regardless of the subjective score. Any observed defect, including a minor cosmetic failure, prevents production release until repaired and rechecked. Apply the full [Quality assurance](quality-assurance.md) and [Video reviewer](video-reviewer.md) procedures, including actual viewing and listening, rather than treating this table as a replacement.

| Check | Required evidence |
| --- | --- |
| Roles and requested outputs | Correct source/reference assignment, exact requested set and honest per-variant status; references never add jobs |
| Authorized edits only | Source-to-output mappings respect allowed trim, reorder, crop, speed and replacement scope; protected words/meaning/actions retained |
| Source and caption accuracy | Reviewed transcript/cues where speech exists; no fabricated speech, incorrect negations, names or unsupported visuals; no transcript invented for silent footage |
| Verified text in every surface | Source-scoped terminology ledger and evidence; all captions, labels, badges, titles, end cards and delivered sidecars agree with verified wording; no guessed proper names, unverified terms or cross-source glossary contamination |
| Face-safe captions and padded badges | Middle caption channel for vertical presenter scenes, measured from moving content; no added text/plate on any face; all glyphs and padding contained inside backgrounds through every animation/text state |
| Sync and audio | Actual listening, lip/action/cue checks, correct source streams, intact tail, no duplicated/masked narration or drift |
| Layout and visibility | Correct shape/composition, protected framing, readable type/holds, visible interface/gestures and acceptable moving cutout edges |
| Presenter-led portrait defaults and overrides | For each of the four 9:16 compositions, a recorded lower-speaker/upper-primary-animation layout and actual delivery-size review; any different position traces to an explicit instruction. No invented presenter on non-presenter footage; horizontal placement follows its own contract |
| Intact source versus alpha foreground | Split/Overlay and source-preserving Adaptive retain the complete original frame and background in the resolved source region. Cutout retains the whole real visible subject with decoded alpha, no rectangular presenter panel, and a graphic background spanning the full canvas |
| Cutout occupancy and usable space | Actual alpha/motion evidence through each cue, safe margins, foreground/background ordering and contrasting-background review; genuine negative space considered inside as well as outside a loose box, with observed reasons for unusable gaps; no collision at raised-arm/hair extremes |
| Purposeful graphic progression | Whole-interval event/state evidence and normal-speed review show semantic development, settled readable labels and short motivated holds. A long unchanged explanatory card with only intro/exit fades, cosmetic jitter, arbitrary loops or unauthorized source edits fails without an applicable explicit stillness instruction |
| Small semantic reveals and smooth handoffs | Per-unit source anchors and actual first-visibility/settled/exit evidence; hidden future descriptions, intact qualifications, adequate reading time, persistent shared geometry and adjacent-frame plus playback checks. No bulk card disguised by highlights, pops/resets, truncated fades or overprinted replacement prose |
| Content-sized panels in available space | Measured contiguous regions after protection/clearance, readable type floor, active-content dimensions and complete animated footprints. Detailed content in a fitting primary region; narrow regions use useful compact cues or remain clear. No fixed side, giant empty box, unreadable shrinking or crowding |

Check speech preservation with source/output comparison and timing evidence; automated transcript equality alone is insufficient because recognition can be wrong. Decode success alone does not establish sync, clarity or resemblance. If a relevant dimension cannot be assessed, mark it unassessed and do not convert missing evidence into a pass.

## Subjective comparison with anchored scores

Rate Reference on the agreed observable attributes: typography, layout, motion, pacing and sound. Compare against named timecoded reference passages, distinguishing justified adaptations from failed matches. Rate Auto on content suitability, clarity, pacing and restraint. Freeze which attributes apply before seeing results; unavailable dimensions stay unassessed, not neutral scores. Keep technical compliance and subjective ratings separate.

Use the same anchored 1–5 scale for both versions, with case-specific examples agreed before testing:

| Score | Reference attribute anchor | Auto attribute anchor |
| --- | --- | --- |
| 1 | Characteristic is absent or seriously contradicts the requested reference | Treatment obscures meaning, distracts or conflicts with the observed content |
| 2 | Recognizable attempt with frequent distracting departures | Useful intent but frequent overload, irrelevant additions or poor holds |
| 3 | Coherent usable interpretation with noticeable inconsistent matches | Clear and suitable overall, with specific pacing/design weaknesses |
| 4 | Strong consistent match to the agreed trait, with sensible documented adaptations | Clear, relevant and restrained treatment with few minor weaknesses |
| 5 | Consistently excellent transfer of the agreed trait at delivery size and speed | Consistently excellent support for this source's meaning, viewing context and timing |

A high resemblance rating cannot excuse removed words or illegible captions. A quiet but well-suited Auto treatment can score higher than a dense one. Purposeful progression is not maximum activity: stable readable labels, motivated short holds and explicit stillness can be correct; an unchanged long explanatory card cannot earn a pass by calling it restrained. Report dimension scores as well as the aggregate so one attractive attribute cannot hide a repeated defect.

## Blinded review, repetition and improvement gates

Randomize candidate order and label paired clips A/B without release/version names. Keep duration/viewing context comparable and provide the source/reference evidence needed for the question. Use independent reviewers where possible; disclose if only the author reviewed. Record each preference as revised win, tie or revised loss after unblinding, together with concrete defects and reasons. Ties count as no win. Repeat representative cases under the same limits to expose variability rather than selecting only the strongest run.

Freeze these proposed quality-first pilot gates before the comparison, or record an explicitly agreed alternative before running it:

1. Every hard acceptance check passes for evaluated outputs, with no unassessed required dimension.
2. Reference improves the median rating over the frozen baseline for the agreed observable reference attributes. Auto improves the median rating for content suitability and clarity. Report separate mode results and name both compared snapshots; 2.0.0 is required only when reproducing that historical comparison.
3. The revised version wins at least two-thirds of blinded paired preferences in each mode; ties remain in the denominator as no win. Report actual win/tie/loss counts and sample size.
4. Median human hands-on repair time does not increase. Measure from first candidate to accepted candidate using the same definition for both versions; record zero when no repair is needed. Keep elapsed processing/render time separate.
5. No tested content type has a repeated serious defect, and explicit presets show no material regression. Predefine serious defects with examples, such as repeated word loss, hidden interface actions, unusable matting or music masking speech.

These are pilot decision rules, not universal reliability guarantees. Several independent held-out sources per mode and preset coverage are needed for a useful result. An undersized set, ties, inconsistent preferences or unassessed dimensions make the visual-quality result inconclusive. Do not weaken a gate after seeing the scores or exclude a failed render without reporting it.

If gates fail, revise from the defects and run a fresh held-out comparison. If only routing improves, report that narrow demonstrated benefit separately.
